# 03 题目自然语言化（step3_nl.py）

把 step2 生成的结构化题面（如"北京南到上海虹桥"）转成口语化购票需求，
作为被测模型的输入题面。产物写**独立文件 metadata_nl.json**，不触碰 metadata.json。

## 1. 接口

```
python step3_nl.py --metadata question/metadata.json --metadata-nl question/metadata_nl.json
    [--ids q1 q2 ...] [--force] [--concurrency 5] [--interactive]
    [--api-key ... --model ... --base-url ...] [--env .env]
```

- 目标筛选：`--ids` 指定题（存在性配对组整组处理）> `--force` 全部 >
  默认（组内任一缺 nl 则整组处理，已有组打印跳过计数）。
- 模型配置优先级：命令行 > `.env`（NL_API_KEY / NL_MODEL→DEFAULT_MODEL /
  NL_BASE_URL→DEFAULT_BASE_URL）；缺失报错退出，不默认任何平台。
- 温度 `NL_TEMPERATURE = 1.4`（common/config.py，实测 glm 系推理模型可接受）；
  超时沿用 `TEST_CHAT_TIMEOUT = 600s`。

## 2. 提示词（题目语义契约，勿随意改动）

模板要点（12 条生成要求，全文见 step3_nl.py 的 `NL_PROMPT_TEMPLATE`）：

1. 口吻任意（尊敬/无奈/请求/无礼…）；
2. **人数与座位等级必须隐含**，禁止"买 X 张""二等座"式硬性表达；
3. 必须保留出发站与到达站；只输出一条回答；不自称"用户"；
4. 约束语序随机、表达可隐讳；不涉及"座位挨着"；
5. 评判标准（综合考虑/最快/最便宜/出发最晚/最早到达）与行为约束
   （不允许换乘 / 不允许买短补长与额外购买）**存在才带出**，且用购票者口吻
   自然表达（如"越快越好""别整换乘那套"），不写"约束：X"。

组装输入仅四项：行程（question）、人数、座位等级中文标签、
（选择性题才有的）评判标准与行为约束块。**不传**题型、分段策略、标答或任何
车票信息——防止题面泄题。

## 3. 分组规则（存在性 0_/1_ 配对一致）

- **存在性题**按「基础题号 + 内容」分组：基础题号 = 去掉数字前缀
  （`0_34`/`1_34` → `34`），内容 = (行程, 人数, 座位, 评判标准文本, 行为约束文本)。
  同组共享同一份 NL，保证 0_/1_ **除干扰外题面完全一致**（对比实验的前提）。
  step2 生成时同 row 的 0_ 复用 1_ 的基础题号（custom_qid 共享），确保配对成立。
- 不同基础题号即使内容相同也不合并（0_34 与 0_35 各自独立生成）。
- 选择性/其他题每题独立成组。
- 组序保持 metadata 首现顺序（输出可复现）。

## 4. 产物文件 metadata_nl.json

- 结构：`{qid: {…主元数据全字段快照…, "nl_question": "文本"}}`。
  首次写入时从 metadata.json 拷贝该题全字段快照；已有快照沿用（保留首轮字段）。
- **写入时机**：每组成功立即落盘（原子写：tmp + os.replace）——批量中断不丢已完成。
- **读取侧**：`database.load_metadata()` 自动把 nl_question 合并回内存视图
  （仅当 qid 仍存在于主文件），下游（step4 取题面、可测性扫描）无感知。
- 删除题目时应同步清理 NL 残留（`database.remove_metadata_nl_qid`）。

## 5. 两种运行模式

### 批量并发（默认）
- `--concurrency` 1~20（LLM 调用为 IO 密集，线程池即可；默认 5）。
- LLM 调用在锁外并发；写 metadata_nl.json 经进程级可重入锁串行化。
- 每组结果实时打印（题号 + 生成文本）；结束输出 生成/失败 计数。
- 失败语义：网络错误 / 429 / 5xx 指数退避重试（≤3 次，退避 min(30, 2^n)+1s）；
  401/400 等参数类错误**不重试**直接失败（`NoRetryError`）；content 为空
  （内容全在思考链）显式报错。单组失败不影响其他组。

### 交互式（--interactive）
- 逐组展示题面 → 生成 → `[Enter]` 保存 / `[x]` 重新生成 / `[n]` 跳过 /
  `Ctrl+C` 中止（已保存的不受影响）。生成失败可选 `[r]` 重试。
- 适合抽样质检 NL 质量；日常流水线用批量模式。

## 6. 与测试的衔接

step4 的可测条件是 `question` 与 `nl_question` 同时存在——因此本步骤是
出题与测试之间的**必经闸口**。`--force` 重生成会直接覆盖旧 NL；
若某题已被测试过（state 有记录），重生成 NL 不会重置 state，
但新旧题面差异会污染对比，建议重生成前先评估。
